怎么在 dsh 里调用{{PRODUCT}}

你接下来连上的不是一个模型，而是一个真人。他收到你的请求后亲手打字回复，所以慢是正常的，也不会秒回。想清楚再问，一次把话说完。

只想赶紧跑通？看 简短版教程（单屏读完，直接照抄）。这一页是完整版，多了排错对照表和原理说明。

别把这一页的地址当成 API 地址

你现在浏览器地址栏里那条（/guide?key=…）是给人看的教程页。 把它填进客户端的「API 地址」会失败，报错长这样：Stream ended without finish_reason —— 因为服务器回的是一页 HTML，不是 SSE 流。
要填的是路径里带 /k/<你的密钥>/v1 的那条，本站首页和下面第 1 节都有。

先知道三件事，能省你很多时间

  • 会很慢。响应时间取决于他在不在电脑前。别设 30 秒超时，那必然失败。
  • 一轮任务要来回好几轮。dsh 是 agent，它拿到一次回复后会继续发下一轮去读文件、跑命令。你得耐心陪它走完。
  • 他可能不按你的剧本走。毕竟是人。他也可以拒绝、可以说"不知道"。

0先装好 dsh

需要 Node.js 18 以上。没有 dsh 就跑下面这条，不用装全局：

npx @deepseek-ai/dsh web

装完之后浏览器打开 http://127.0.0.1:3080，就是 dsh 的 Web UI。

1拿到凭据

向站长要这几项，或者他直接给了你一个带密钥的本页链接（那样下面表格里已经自动填好了）：

Provider IDDOGLLM
基础 URL
API 协议OpenAI Chat Completions
模型 ID{{MODEL}}
API Key随便填，填 dummy 就行

为什么密钥要写在地址里，不能只填密钥栏？

这个服务挂在一层企业级边缘网关上，它会在转发前覆盖掉 Authorization 请求头、并剥掉 x-api-key。所以密钥走请求头是永远通不过的，只能塞进 URL 路径。别想着改回标准写法，那样一定 401。

2配给 dsh

两种方式，选一种就行。

Web UI（推荐）
settings.yaml

打开 dsh Web UI，进 Settings → Models → 添加自定义提供方，按下面填：

Provider IDDOGLLM
显示名称我自己
基础 URL
API 协议OpenAI Chat Completions
API Keydummy
模型列表手动填 {{MODEL}}

保存后，在会话里把模型切成 {{MODEL}} 就能用了。

Provider ID 保存后永久不可改

填错了只能删掉重建。DOGLLM 大小写敏感：YAML 里的键名、下面 provider: 的值、这里的 Provider ID，三处必须一模一样，写成 dogllm 就是另一个提供方了。

编辑 ~/.dsh/settings.yaml（Windows 是 C:\Users\你的用户名\.dsh\settings.yaml）。文件不存在就新建：

llm-pi-ai:
  providers:
    DOGLLM:
      apiKeyEnv: DOGLLM_API_KEY
      api: openai-completions
      # ↓↓↓ 注意：下面这一行的密钥段必须换成真密钥，原样保留会报「API密钥无效」 ↓↓↓
      baseURL: {{ORIGIN}}/k/YOUR_API_KEY/v1
      models:
        - id: {{MODEL}}
          name: {{MODEL}}
          contextWindow: 200000
          maxTokens: 8192
agent-default-model:
  provider: DOGLLM
  model: {{MODEL}}

然后让 dsh 能拿到一个非空的凭据 —— 拿不到它会直接报 MISSING_CREDENTIAL，连请求都不发：

export DOGLLM_API_KEY=dummy
dsh web

值是什么无所谓 —— 真正管用的密钥在 URL 里，它只是个占位。Windows PowerShell 里换成 $env:DOGLLM_API_KEY="dummy"。 不想动环境变量也行：在 dsh 的凭据设置里存一条名为 DOGLLM_API_KEY 的记录（dsh 会写进 ~/.dsh/.credentials.yaml 的 refs: 下），效果一样。

如果你之前已经配过别的 provider

把 DOGLLM: 这一段追加到已有的 providers: 下面，不要新写一个 llm-pi-ai: 节点 —— YAML 里同名的键会互相覆盖，那样你原来的模型配置会全部消失。

改了没反应？看看是不是改错了文件

dsh 的配置有两个可能的位置：全局的 ~/.dsh/settings.yaml， 以及每个 profile 自己的补丁层 ~/.dsh/profiles/<profile>/cordis.patch.yml。 如果你是用 Web UI 配的，实际落盘多半在后者（这台机器上就是 ~/.dsh/profiles/desktop/cordis.patch.yml）。改完记得完全退出 dsh 再启动， 它只在启动时读配置。

3验证一下通没通

跑这条，然后去干点别的，等站长回复：

dsh --profile headless "请只回复两个字：收到"

正常应该是这样

等一会儿（可能几分钟），终端会吐出 收到，然后进程正常退出。这说明整条链路通了。

如果卡住不动，先别急着 Ctrl+C —— 大概率只是他还没回。等够 5 分钟再说。

4用起来会是什么样

dsh 每次会话第一发请求就会带上 25 个工具定义：

create_goal  edit  glob  grep  pwsh  read  read_image  subagent
todo_write  web_fetch  web_search  write  ...

这是标准 OpenAI function calling。意味着：

  • 他可以让你批准一个工具调用（比如"读这个文件"），然后 dsh 会真的去执行，再把结果发回来。
  • 一个稍复杂的任务（"帮我看看这个仓库结构"）通常需要他回 3～10 轮。这不是出故障了，是正常流程。
  • 所以别扔一个大任务然后走开，你俩得对着耗。

5出问题了？对号入座

MISSING_CREDENTIAL凭据没解析到。执行 export DOGLLM_API_KEY=dummy 再启动，或在 dsh 的凭据库里存一条名为 DOGLLM_API_KEY 的记录（值随便填）
400 / 404地址末尾的 /v1 漏了
API密钥无效 / AUTH / 401最常见的一种。地址里的密钥段没替换 —— 检查是不是还留着 YOUR_API_KEY 这几个字，那是占位符，必须换成站长给你的真密钥。整段应该是 .../k/sk-me-xxxx/v1，/k/ 和结尾的 /v1 都不能少
model not found模型 ID 必须填 {{MODEL}}，其它名字不存在
卡住不动 / 超时最常见的情况：真人还没回。等够 5 分钟。stream_idle_timeout_ms 默认 5 分钟，可以调大
reply 内容很奇怪正常。对面是人，可以随时打断、重新说清楚你的需求
429 Rate limit发太快了，一分钟 30 次上限。你也不是在跟 API 说话，慢点

6礼貌提醒

  • 密钥只给你自己用，别外传。站长可以随时单独吊销你的那把。
  • 别拿它跑批量任务或自动化流水线 —— 每一条请求都要占用一个真人的注意力。
  • 深夜发长任务之前，想想对面那个人是不是该睡了。
